# 証明の目録

nyxis が Lean で証明している定理と、それぞれが述べないことの一覧。信頼する仮定は [ASSUMPTIONS.md](../ASSUMPTIONS.md)、
仮定を支える接続コードの作り(責務)は [docs/connection.md](connection.md)。

`Test/Axioms.lean` が `lake build` で検査する(`Nyxis.*` の全定理を列挙する)。定理の Lean 文と日本語の読み下しは
各定義と同じファイルにある。

## 接続コード(Assumption 1 のうち証明済みの部分)

純粋な復号・復元・SQL 計画の定理は、Lean 上の入力と成功した返り値の関係を述べる。IO 関数の定理は、
正常終了を前提に返り値と連続する IO 状態を述べる。`serve_handler`・`wrap_options` 等は処理の等式を述べる。
いずれも FFI の外界の振る舞い・外部 DB の実状態・TLS・暗号・時計値の正しさは含まない。
返却 HTTP 応答の構造を述べる定理は応答取得の成功も前提にする。非 health の実入口から本文取得・認証・DB 処理・
応答構築までを結ぶ定理は、本文読み取りの即時完了を前提にする。
IO の `bind` と `mapM` の正常終了を分解する共通の補題は `Nyxis/Internal/IOTrace.lean`。

## 接続コードの証明に向けた方針

Assumption 1 の接続コード全体の対応は未証明であり、統合テストの成功を形式証明とみなさない。証明できた部分は上の表に定理と対象実装を記載し、
信頼対象から外す。外部の IO や FFI に依存することだけを理由に接続コード全体を証明不可能と断定しない。証明できない部分は、

必要なら、引き続き人間の判断に委ねる。

以下は Assumption 1(旧 A4)の接続コードの内訳であり、新たな仮定ではない。各処理は実装済みだが、列挙した対応の証明は未実装である。

- **HTTP の入口と出口**: 生 HTTP の復号、`Std.Http.Body.Stream.readAll` の内部、task として返る非同期処理の継続、
